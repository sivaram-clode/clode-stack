# clode-stack

Local docker-compose for the whole clode platform. Service sources are
siblings of this dir (`../raksha`, `../jumbo`, …); this folder is the
only place compose, env, and seed data live.

## Ingress model — traefik, one entry point

All HTTP flows through the `traefik` service on **host port 8080**,
routed by Host header from per-service docker labels:
`http://<svc>.localhost:8080` (resolves to loopback natively — no
/etc/hosts). Adding a service to the ingress = 3 labels on its own
compose block; routes appear/disappear with the containers, profiles
included. No per-service host ports exist for HTTP — only non-HTTP wire
protocols are published directly (postgres 15432, redis 16379, databend
13307/18000, louie gRPC 8600). Dashboard: `http://traefik.localhost:8080`.

Names that *containers* dial (S3 signing host, OAuth token endpoint,
agent callbacks, CDP) are network-aliased to traefik on the `clode`
bridge, so one URL string is valid from host and containers alike.

The stack is **fully local by default** — Cloudflare is opt-in:
`./stack.sh up --public` starts cloudflared (compose profile `public`,
single catch-all ingress rule `*.srclode.online → traefik:8080`) and
exports `STACK_SCHEME/STACK_DOMAIN/STACK_PORT/STACK_TUNNEL_DOMAIN` so
outward-facing URL values interpolate to `https://<svc>.srclode.online`.
Only inbound-from-internet paths need it: Resend delivery webhooks
(notify), Slack OAuth install + Telegram webhook (chil), GitHub App
callbacks (gitana), Composio callbacks (toolkit-proxy), external MCP
clients, shareable louie tunnel URLs. up.sh prints the applicable
warnings per running service in local mode.

Services never CF-exposed (ec2mock, ikki, minio-console, narnia, the
traefik dashboard) carry a `.localhost`-only router rule — do NOT add
srclode rules to them; ec2mock's admin API is unauthenticated.

## Layout

```
clode-stack/
├── docker-compose.yml         compose source of truth — services, anchors, `clode` bridge
├── docker-compose.cache.yml   BuildKit cache-mount overlay (generated by scripts/gen-build-cache.sh)
├── cloudflared-config.yml     single catch-all rule (*.srclode.online → traefik); mounted into cloudflared (`public` profile)
├── stack.sh                   single entrypoint dispatching to scripts/
├── scripts/                   up.sh, down.sh, wipe.sh, seed.sh, cleanup.sh, tail-logs.sh, gen-build-cache.sh,
│                              seed-skills-from-local.py (emits SQL piped into psql by seed.sh),
│                              lib/agent-sweep.sh (image resolution + container/volume sweep shared by cleanup.sh + wipe.sh)
├── db/init-multiple-dbs.sql   CREATE DATABASE per service (postgres init — first-boot only)
├── data/                      seeder inputs (workflow-templates, kairo config, skill overrides)
├── docs/                      operator guides — see "Guides" below
├── build-cache/               generated cache-mount Dockerfiles (regenerated every up)
└── logs/service/             rolling per-svc container log files (down.sh prunes to newest 10 per dir)
```

## Quick start

```bash
# Provider tokens (CLAUDE_CODE_OAUTH_TOKEN, ANTHROPIC_API_KEY, OPENAI_API_KEY,
# CODEX_OAUTH_TOKEN+REFRESH) live in ../mang-proxy/.env — stack doesn't load them.

./stack.sh up                  # build + up + seed (idempotent) — fully local, no Cloudflare
./stack.sh up --public         # + cloudflared edge (webhooks, OAuth installs, external MCP clients)
./stack.sh up jumbo brahmi     # subset; seeder skipped on partial bring-ups
./stack.sh up --agent          # + build the full benji agent image (../benji/Dockerfile) and flip brahmi to aramb-vm
./stack.sh down                # stop; preserves volumes/images/buildkit cache
./stack.sh wipe                # total teardown (agents + volumes + images + buildkit) — prompts y/N
./stack.sh cleanup             # truncate data in place — see `stack.sh cleanup -h`
./stack.sh reseed              # cleanup -a -y --reseed (data reset + fresh seed)
./stack.sh seed                # re-run seed against a running stack
```

`BUILD_BATCH_SIZE=N` (or `--batch N`) caps concurrent Go builds (default 2,
max 6).

## Automated UI testing — oauth-mock lets a browser sign in

Real Google/GitHub consent screens can't be driven by an automated (CDP)
browser, so raksha's OAuth is pointed at the local **oauth-mock** service
(`docker/oauth-mock/`, `.localhost`-only, never CF-exposed). It renders a plain
HTML form standing in for the provider consent screen: enter **any email**,
Approve, and raksha completes a real sign-in and creates a **real user** — so a
headless agent can log in and exercise the app end to end.

- **Wiring:** the raksha block sets `GOOGLE_OAUTH_BASE_URL:
  http://oauth-mock.localhost:8080`. One base covers all three endpoints
  (`{base}/o/oauth2/auth`, `/token`, `/oauth2/v2/userinfo`); the alias resolves
  from both the browser and the raksha container. The mock ignores client creds,
  so the real `GOOGLE_CLIENT_ID` from `../raksha/.env` is reused unchanged. Unset
  the var (comment it out) to fall back to real Google. GitHub is also served by
  the mock, but `GITHUB_OAUTH_BASE_URL` is **not** wired yet — the GitHub button
  still hits real github.com.
- **Identity is derived from the email**, deterministically: `bob.smith@x.io`
  → name "Bob Smith", stable id. Same email = same user (returning-user path);
  a fresh email = a new signup. `DEFAULT_EMAIL` (compose) prefills the field.
- **Flow:** browser loads `http://localhost:3001` → `/login` → "Continue with
  Google" → mock consent form → Approve → raksha callback
  (`localhost:8080/raksha/auth/oauth/callback/google`) → back into console-web
  (new user with no plan → `/pricing`). Verify:
  `docker exec clode-db-1 psql -U postgres -d raksha -c "SELECT id,email,name FROM users WHERE email='…';"`
- The user-level **`clode-stack`** skill carries the operational how-to
  (chrome-mcp steps, workspace/feature-branch selection, datastore queries).

## Raksha's seed is BUILT IN — the fresh-stack deadlock fix

raksha validates at boot that the NOTIFY/CHACHING admin identity rows
exist (missing = fatal crashloop). Seeding them post-up used to deadlock a
fresh stack: `up -d` waits on raksha healthy, the seeder runs after `up -d`
returns. Fix: `gen-build-cache.sh` appends `seeds/raksha-seed.sql` onto the
LAST embedded migration file inside the generated Dockerfile, so
`raksha migrate` itself plants the rows on a fresh database before `serve`
starts. No new migration version is created (upstream numbering stays
untouched). Already-migrated databases skip it — the two flows that
matter there both re-apply the same SQL themselves: `cleanup --postgres`
pipes seeds/raksha-seed.sql right after truncating (truncate keeps
schema_migrations, so migrate would no-op — without the re-apply raksha
crashloops and the next up hangs on its health gate), and scripts/seed.sh
stays the idempotent backstop for everything else. To give another
service a build-time seed: one entry in gen-build-cache.sh's
`SEED_MIGRATION_DIRS` + `seeds/<svc>-seed.sql`.

## Seeder model — compose is the source of truth

`scripts/seed.sh` does not carry a hardcoded list of services. On every run
it queries `docker compose ps --services --status running,restarting,created`
to build a `RUNNING` set, then reads each running container's `DB_NAME` env
via `docker inspect` to build a `SVC_DB` map (service → postgres db). Every
seed step is gated `if in_scope <svc> [ && in_scope <dep> ]`, so:

- Profile flags at up-time (`--profile skills`, `--profile deploy`, …)
  automatically scope what gets seeded — no `if profile == …` in seed.sh.
- `./stack.sh seed` invoked bare (no profile flag on the shell) sees the
  same containers that are up, because RUNNING is runtime state, not a
  re-render of the compose config.
- Removing a service, moving one to a profile, or adding a new one only
  needs a compose edit — the seeder auto-adjusts.

**Load-bearing convention: `DB_NAME` on a service.** The DB-creation loop
and the "kick restart-loopers" step both key off `DB_NAME` in the running
container's environment (set via `x-db-common` anchor + per-service
override). If you introduce a service tomorrow that uses `DATABASE_URL` or
`POSTGRES_DB` instead, the seeder won't create its DB — update
`scripts/seed.sh`'s discovery block to teach it the new key.

Cross-step dependencies stay explicit in seed.sh gates (`in_scope
skills-registry && in_scope raksha` — no JWT auth without raksha). New
seed logic for a new service is one `if in_scope <svc>; then …; fi` block
against its own DB; no separate registration step.

## Gotchas

- **console-web is the dev-server exception to the ingress model.** It's the
  one HTTP service that publishes a host port (`3001:3001`) instead of routing
  through traefik, and the one service that is NOT built — `oven/bun` runs
  `bun run dev` over a bind-mounted source for hot reload (part of the default
  stack, browser at `http://localhost:3001`).
  Reasons the port is published rather than traefik-routed: Vite's HMR
  websocket wants the dev server on the browser's own origin, and Vite ≥7
  host-checks any non-localhost Host, so `console-web.localhost:8080` would
  need `server.allowedHosts` + `hmr.clientPort` edits in the repo's
  vite.config.ts. `node_modules` is a named volume (container-native binaries,
  shadows the host's); install uses `bun install --backend=copyfile` because
  bun's default hardlink backend can't link from its in-image cache across the
  filesystem boundary into that volume. Config comes from the MAIN repo's
  `.env.local` even under a worktree override (it's gitignored, so a fresh
  worktree lacks it — Vite still exposes the `VITE_*` vars from the container
  env). The bind-mount source honors `CONSOLE_WEB_DIR` from `workspaces.yaml`
  like every other service.
- **`minio-setup` is a one-shot init container.** `restart: "no"`; creates
  the `databend` and `brahmi-attachments` buckets then exits. `compose ps`
  shows `Exited (0)` — that's healthy. databend's `depends_on` uses
  `service_completed_successfully` against it.
- **One redis, two logical DBs.** mang-proxy hard-fails on empty
  `REDIS_PASSWORD`, so redis runs with `--requirepass clode-redis-local`.
  mang-proxy uses DB 1; raksha + brahmi use DB 0 — keeps
  `cleanup --redis` independent of `cleanup --redis-mang`.
- **Two classes of agent containers live outside compose.** (a) pool-manager
  in `LOCAL_MODE=true` mounts `/var/run/docker.sock` and `docker run`s
  kairo containers on the `clode` bridge. (b) ec2mock spawns aramb-vm
  containers named `i-<hex>` for RunInstances and labels each with
  `aws.mock.instance-id` + creates a named volume labeled
  `aws.mock.owned=true`. Compose can't see either. `scripts/lib/agent-sweep.sh`
  centralises the sweep — cleanup.sh's `--agents` and wipe.sh both call
  through it (containers by label ∪ image ∩ `network=clode`; volumes by
  label). Image resolution unions ec2mock's `GET /_admin/config/default-image`,
  `data/pool-manager-svc-configs.json`, `$BENJI_IMAGE`, and the three
  static local tier tags (`clode-stack/benji:{dev,vm,voice}`) so containers
  launched under a previous `--agent` mode still get swept.
- **`x-admin-ids` UUIDs move as a unit.** The admin UUID and the
  raksha-chaching bot UUID each live under several names: the admin org/user
  drives `ADMIN_USER_ID(S)` / `ADMIN_ORG_ID(S)` / `POOL_OWNER_ID` /
  seed.sh's JWT sub; the chaching bot (`CHACHING_ADMIN_*`) ALSO appears in
  `ADMIN_USER_IDS` (mang-proxy/ikki gate cha-ching's outbound SA tokens by
  JWT user.id) and `ADMIN_ORG_IDS` (cha-ching gates raksha's intake/merge
  tokens by organization_id — post org-pivot cha-ching ignores
  ADMIN_USER_IDS entirely; an anchor without ADMIN_ORG_IDS = every raksha
  reconciler call 403s). To rotate: edit the anchor AND the hard-coded
  `ADMIN_USER_ID` near the top of `scripts/seed.sh` AND the UUIDs in
  `seeds/raksha-seed.sql` (the build-time raksha seed), then
  `./stack.sh wipe && ./stack.sh up`.
- **postgres init runs only on first volume creation.** A new per-service
  DB added later is absent at service boot → migrate crashes → restart
  loop. `scripts/seed.sh` backfills any missing DB (discovered from live
  containers' `DB_NAME` — see "Seeder model" above) and bounces the
  affected service.
- **`./stack.sh wipe` prunes BuildKit cache globally.** Cache mounts are
  anonymous and unlabeled, so the prune hits every other docker project on
  the host. `--wipe` is the explicit opt-in.
- **Cloudflare edge rewrites `Accept-Encoding` → SigV4 breakage for
  `aws-sdk-go-v2` through `minio.srclode.online` (--public only).** CF's edge
  unconditionally sets `Accept-Encoding: gzip, br` on every request before it
  reaches the tunnel. `aws-sdk-go-v2` includes Accept-Encoding in its SigV4
  signed-headers list (`boto3`/aws-cli/`mc` don't), so the value the client
  signs (`identity`) and what MinIO validates against (`gzip, br`) diverge →
  `403 SignatureDoesNotMatch` on every PUT/GET. Verified with a hand-rolled
  SigV4 truth table: signing `identity` + wire=identity fails via CF but
  passes direct; signing `gzip, br` + wire=identity passes via CF but fails
  direct; dropping AE from the signed-headers set passes both ways. Blast
  radius is exactly that one header — Host / X-Amz-Date / X-Amz-Content-Sha256
  / body all survive CF intact. CF blocks Accept-Encoding manipulation from
  Transform Rules / Workers / Snippets, so the fix has to live origin-side.
  **Fix in place:** the `ae-identity` traefik middleware (declared on the
  traefik service labels, attached to the minio router) pins
  `Accept-Encoding: identity` before proxying to `minio:9000`. traefik
  passes Host through untouched (SigV4 signs Host too) and streams bodies
  unbuffered (STREAMING-AWS4-HMAC-SHA256-PAYLOAD compatible). This replaced
  the dedicated `minio-proxy` nginx shim — its config and the SigV4
  truth-table repro tests are retained at `docker/minio-proxy/` for
  reference; the tests still prove the CF behavior if repointed at the
  traefik-fronted hostname. Local traffic never touches CF, so the
  middleware is a no-op there.

  Consumers whose presigned URLs leave the container (brahmi attachments,
  intervix + ikki recordings, vova audio) sign against the traefik minio
  origin (`http://minio.localhost:8080` local / `https://minio.srclode.online`
  public — network aliases make both resolvable in-network), shared via the
  `x-s3-common` / `x-minio-endpoint` compose anchors. databend is the sole
  backend that stays on `http://minio:9000` direct (internal storage engine,
  never presigned) with its own `AWS_S3_*` env. Desktop tools: `mc alias set local
  http://minio.localhost:8080 minioadmin minioadmin`; console at
  `http://minio-console.localhost:8080`.

  **When you suspect the ingress is your bug:**
  1. `curl -s http://minio.localhost:8080/minio/health/live` → 200 means
     traefik routing + minio alive. Fails → check `docker logs
     clode-traefik-1` and that the minio router labels are present
     (`http://traefik.localhost:8080` dashboard lists every router).
  2. SigV4 403s via `--public` only → verify ae-identity is attached:
     the request's Accept-Encoding must arrive at minio as `identity`.
     The `docker/minio-proxy/tests/*.sh` openssl signers reproduce the
     truth table when pointed at the public hostname.

- **Cloudflared: ingress rule ≠ DNS routing.** An entry in
  `cloudflared-config.yml` only tells the tunnel HOW to forward; the
  hostname still needs a Cloudflare DNS CNAME. Today this is covered by a
  wildcard CNAME `*.srclode.online` on the clode-stack tunnel
  (`cf6cb58d-b43b-4e84-9c68-cf14652c9fc4`) — new ingress rules light up
  without a DNS step. If the wildcard ever gets clobbered, restore:
  ```
  docker exec clode-cloudflared-1 cloudflared tunnel \
    --origincert /secrets/cert.pem \
    route dns --overwrite-dns cf6cb58d-b43b-4e84-9c68-cf14652c9fc4 '*.srclode.online'
  ```
  Probe a random subdomain to verify: working wildcard → 404 (tunnel
  fallback), missing → 530 (Cloudflare edge).
